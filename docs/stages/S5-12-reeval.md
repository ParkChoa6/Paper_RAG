```

----------------------------------------------------------------------------------------------------

oracle          93%     0     0        0          2       100%      86%     1.3
```

### 2.1 ★★ 这一列反过来了

S5-6 的结论是「rerank 在检索层 +18 点，合规回答 79% vs 79%，一点没动」。
现在：**dense 89% > rerank 82%**，反而 dense 高。

**但这不是"rerank 变差了"，是"dense 的那 3 个解析失败没了"：**

- S5-6 的 dense：3 个 `parse_failed`（Q6/Q13/Q24）+ 2 个拒答 → 22/28
- 现在的 dense：0 个 `parse_failed` + 1 个拒答 + 1 个可疑 → 25/28
- S5-10 已经算过：**把那 3 个「崩」当成修好，dense 上限就是 21/28**（答对率口径）
  或 25/28（合规口径）—— 和现在实测的一模一样。

### 2.2 ⚠️ 别把这个差当结论

配对 McNemar：合规回答 dense → rerank，b=4 c=2，**p=0.683**。
落进噪声里 —— 和 S5-10 §4.2 说的一样，28 题分不出 7 个点。

> 能说的：**S5-7 修的东西真的传导到了中间指标上（dense 25/28）**。
> 不能说的：dense 现在比 rerank 好。

### 2.3 检索层那一列没动

`材料含答案` 71% vs 89%，和 S5-6 一字不差 —— 符合预期：
S5-7/S5-11 改的都是**生成之后的环节**，检索没碰。
这算一次隐含的回归测试：**改了生成层，检索层的数不该动。**

89% 比 82% 大 7 个点。第一反应是"rerank 退化了"。

而 rerank 本来就是 0 个 —— 一次修复只对**有病的那一臂**有效。
