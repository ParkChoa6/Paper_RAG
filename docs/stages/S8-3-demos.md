## 2. 为什么这么写

### 2.1 为什么演示必须包含一段失败的

只放成功案例的演示，读者会把 `✓ 引用校验通过` 读成"答案可信"。
**它不等于。** 它只等于"引文没有伪造"。

§4 那段是特意找的：一个**话题相邻、但语料里没有答案**的问题。它同时暴露三件事：

1. 检索分数从 0.96 掉到 **0.52** —— 检索层其实"知道"没好材料，但它没有说出口；
2. 模型不拒答，答得不完整；
3. 引文**逐字为真**，但根本不支持结论 → `verify` 全放行。

> 把失败案例从演示里拿掉，等于用演示给结论做背书。
> **演示的职责是让人校准预期，不是让人佩服。**

### 2.2 为什么 DEMOS.md 单独成文，不塞进 README

README 已经 400 多行。再塞六段原始输出（其中一段是 5 条材料的完整 JSON）会变成：

```
读者滑到这里 → 看到一大段终端输出 → 直接关掉
```

所以分工是：**README 回答"这是什么"，DEMOS 回答"它看起来怎么样"。**
README §1 保留一个**格式示意**并明确标注"不是逐字记录" —— 因为示意要短，逐字记录要全，两者不能是同一段。

### 2.3 为什么数字后面要跟一句"每次跑都会变"

DEMOS 里每次出现的 `+0.9629`、`12.7s` 都是**这一次**的数。
不提前说清楚，下一个人复现出 `+0.9541` 时会以为"文档是编的"或者"代码坏了"。
真正的判据只有一个：**结构**（谁说的哪一行）不会变。

### 2.4 为什么"没证明什么"要单列一节

因为一份演示最容易造成的误读，是把**六段**当成**整体能力**：

| 演示给了 | 容易被读成 |
|---|---|
| 六段都跑通了 | 它答得都对 |
| `✓ 引用校验通过` | 引用没问题 = 答案没问题 |
| 缓存 18ms | 它很快（实际冷启动 13~19s） |
| 拒答能触发 | 它能识别"不知道"（§4 证明它不能） |

第 8 节逐条顶回去。**这一节比前七节加起来更该读。**

## 3. 不应该怎么写

### 3.1 ❌ 手写"示例输出"

我没有让模型"生成一段看起来像本次运行"的输出。每一段都是**先跑、再贴**，
包括那段不想要的（§4，以及 probe_cite 里 3/8 次"没编"的反例）。

理由和 S5-7 的"标定仪器"是同一条：**输出的格式可以想象，输出的内容不能。**

### 3.2 ❌ 把 §4 那段删掉，只留"成功的样子"

见 2.1。删掉它，这份文档就从"记录"变成了"宣传"。

### 3.3 ❌ 在 DEMOS 里给答案打"正确/错误"的批次结论

§4 说"答得不完整"，是因为 BERT 的预训练目标确实有 MLM + NSP 两个（这是公开事实），
不是因为我判了卷。**文档里不做判卷** —— 判卷在第 5 节那张 84 格表里，
人判的、逐格理由落盘、可复核。两者的强度不一样，不能混着用。

### 3.4 ❌ 看到中文乱码就说"服务端编码有问题"

见 §4.4 —— 这是本步唯一一次差点修错地方。

## 4. 怎么验证它真的对了

### 4.1 六段都重跑过

本文档里每一段输出，都来自本次会话里**真跑**的那一次（不是上一次的记忆）。
两条命令的耗时差异（retrieve 25.36s vs 12.12s）正好是
"重排权重在不在内存"的差 —— 这个差本身就是证据：两段来自两个不同进程。

### 4.2 数字对得上

| 出现在 | 数字 | 在哪能对上 |
|---|---|---|
| §1 首页 | `语料 1345 条 · 索引 (1345, 1024)` | `/api/health` 的 `chunks` / `dim` |
| §5.1 | `load_seconds: 0.15` | 后端日志「就绪 … 用时 0.15s」 |
| §5.3 | `n_asks: 2, n_cache_hits: 2` | 发过 3 次请求、1 次命中缓存 |
| §6.2 | `5/8 次编了` | probe_cite 自己的结尾统计行 |

★ 一条对不上就说明贴错了段。**能对上是这类文档唯一的质量检查。**

### 4.3 probe 的退出码

`probe_cite.py` 结尾是 `✅ 通过 … 退出码 = 0`，`probe_ui.py` 是 `19/19 通过`。
引用这两处时看的是**它自己的结论**，不是"我跑完了没报错"。

### 4.4 ⚠️ 那个坑：PowerShell 5.1 把中文 JSON 显示成乱码

采 §5.2 的响应时，用 `Invoke-RestMethod` 拿回来是这样：

```

```

**第一反应是"服务端编码坏了"。** 错。三分钟后用另一种客户端（urllib + 显式 UTF-8）拿到：


## 5. 要补的概念

- **媒体类型与字符集**：`Content-Type: application/json` 本身不带字符集，
  JSON 规范默认 UTF-8。但 PowerShell 5.1 的 `Invoke-RestMethod` 在部分场景
  会按系统 ANSI 代码页解码 —— 客户端行为，不是协议问题。
- **`Accept-Charset` / 显式 UTF-8 解码**：跨平台读写 JSON 时，
  显式 `decode('utf-8')` 比"相信默认"稳。
- **演示 vs 评测**：演示证明"能跑"，评测证明"有多好"。前者 n=6，后者 n=28。
  把演示当评测用，就是又一次"用感觉代替尺子"。
